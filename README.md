## 1. Description
The `g51` repository provides a specialized, low-level monitor program engineered for the MCS-51 (8051) architecture. Operating as a bare-metal debugging assistant, it establishes a reliable communication interface over serial (UART), parses host commands, manages memory execution spaces, and facilitates direct system inspection on target silicon or emulator environments.

## 2. Purpose
The primary objective of the `g51` monitor project is to provide a lightweight, independent development and testing utility that acts as an alternative to proprietary hardware debuggers. Key system objectives include:
* **Runtime Introspection:** Enabling real-time interrogation and modification of Special Function Registers (SFRs), internal RAM, and external memory blocks.
* **Firmware Deployment Validation:** Assisting developers in loading, parsing, and verifying execution binaries safely inside localized memory regions.
* **Simulation & Hardware Alignment:** Ensuring seamless transition phases between software emulators (e.g., `ucsim`) and live target microcontrollers.

## 3. Directory Contents
The repository is systematically organized to isolate compilation outputs, simulation configurations, source blocks, and functional validation files into specific environments:

### 📁 `/bin`
Contains the compiled binary distributions, executable artifacts, and final hex targets (e.g., `.hex`, `.bin`) generated by the compiler tools.

### 📁 `/cfg`
Houses the environment configurations and hardware profile definitions. This includes dedicated layout scripts for the **ucsim** emulator to replicate hardware boundaries, memory mappings, and peripheral states during automated validation phases.

### 📁 `/src`
The core implementation directory containing the source code files (`.c` or `.asm`). It encapsulates the primary logic loops, interrupt service routines, UART driver abstractions, and the main command parsing engine.

### 📁 `/inc`
Holds the project's header files (`.h`) and definition scripts, mapping out Special Function Register addresses, functional macro loops, and global system variables.

### 📁 `/test`
A validation test suite containing specialized source routines and pre-compiled binaries designed explicitly to test the functionality and integrity of the monitor's `load` command.
